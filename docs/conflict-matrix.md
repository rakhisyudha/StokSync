# StokSync conflict matrix

This matrix is the v1 source of truth for conflict behavior. It complements the protocol contract in [sync-protocol.md](sync-protocol.md) and the architecture design in [`.kiro/specs/stoksync/design.md`](../.kiro/specs/stoksync/design.md). The governing decisions are recorded in [ADR 0012: conflict policies and explicit resolution](adr/0012-conflict-policies-and-explicit-resolution.md) and [ADR 0009: deterministic concurrent stocktake policy](adr/0009-deterministic-stocktake-conflicts.md). Each policy preserves local intent or immutable history; no rejected intent is silently discarded.

| Scenario | Canonical policy | Client behavior | Automated evidence |
|---|---|---|---|
| Independent movement creation | Retain both valid immutable movements and derive the balance from their sum. | No conflict is created solely because the devices were offline. | `app/test/integration/two_device_convergence_test.dart` (`converges two independent replicas through the authenticated runtime`); `server/internal/sync/operations_test.go` (`TestServiceAppendsIndependentMovementsFromDifferentDevices`). |
| Same product, disjoint field edits | The first accepted edit creates the current version. A later stale edit compares base, local, and canonical values field-by-field. | Auto-merge only disjoint editable fields; keep the original as audit history and queue a new upsert using the current server version. | `app/test/data/local/product_three_way_merge_test.dart`; `app/test/data/local/sync_response_reconciler_test.dart` (`auto-merges disjoint product fields into a current-version follow-up`). |
| Same product, overlapping field edits | The first accepted edit remains canonical; the later edit is rejected with `version_conflict` and canonical state. | Retain a blocked operation and an unresolved conflict with base, local, and server payloads for an explicit resolution action. | `app/test/data/local/product_three_way_merge_test.dart` (`does not merge overlapping edits even when values match`); `app/test/data/local/sync_response_reconciler_test.dart` (`keeps overlapping product edits as an unresolved conflict`). |
| Duplicate active barcode | PostgreSQL's active-barcode unique index rejects the contender and returns the owning canonical product. | Retain the contender's local intent and canonical owner. The user may queue an explicit retry without the conflicting barcode. | `server/internal/sync/postgres_integration_test.go` (`TestPostgresDuplicateBarcodeConflictReturnsCanonicalOwner`); `app/test/data/local/conflict_resolution_repository_test.dart` (`barcode resolution retries without the conflicting barcode`). |
| Product edit versus tombstone | A tombstone wins in either arrival order; no edit may resurrect a deleted product. | Apply the canonical tombstone, retain the rejected edit and its conflict history, and offer only acknowledgement rather than resurrection. | `server/internal/sync/postgres_integration_test.go` (`TestPostgresDeleteWinsAgainstAnAlreadyAcceptedEdit`); `app/test/data/local/sync_response_reconciler_test.dart` (`applies a canonical tombstone for a rejected edit without dropping audit intent`). |
| Correction or reversal | A correction is a new immutable `adjust` movement linked through `reverses_id`; historical movement rows are never updated or deleted. | Append each valid correction locally and sync it as `add_movement`. Audit history stays visible as a reversal chain. | `app/test/data/local/local_mutation_repositories_test.dart` (`conflict matrix correction appends an immutable reversal chain`); `server/internal/movements/postgres_integration_test.go` (`TestPostgresCanonicalDomainTransactions`). |
| Concurrent stocktakes | The server recomputes each delta from the locked canonical ledger and orders stocktakes by `(occurred_at, movement_id)`. The greater key is canonical; stale/displaced intent receives a structured outcome. | Retain displaced intent as `stocktake_displaced` conflict history; never rewrite an immutable movement. | `server/internal/movements/service_test.go` (`TestConcurrentStocktakesUseTheSameCanonicalWinnerRegardlessOfArrivalOrder`); `app/test/data/local/sync_response_reconciler_test.dart` (`replaces a stale local stocktake delta with the canonical delta and repairs its projection`). |

## Status semantics

`pending_ops` records all unsynchronized and terminal local intent for auditability. The sync-status **pending** count deliberately includes only actionable work (`queued`, `retrying`, or `inflight`) and excludes `blocked` rows. Blocked rows remain available through the conflict list and contribute to the unresolved conflict count until explicitly resolved or auto-merged. This prevents an auto-merged source operation from leaving the pending indicator permanently elevated while preserving the original intent.
